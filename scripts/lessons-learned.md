# Висновки та правила для наступних ігор серії "Catch the Killer"

Цей документ створено для того, щоб під час розробки або адаптації веб-застосунків для наступних ігор серії ми не повторювали попередніх помилок і враховували специфіку локального запуску та PWA.

## 1. Локальний запуск (протокол `file:///`) та CORS
Оскільки багато користувачів будуть запускати застосунок просто подвійним кліком по `index.html` з розпакованого архіву (без локального сервера), браузер застосовує жорсткі правила CORS.

**Граблі, на які ми наступили:**
- Використання ES6-модулів (`<script type="module">`). Браузер блокує їхнє завантаження через `file:///`.
- Використання `fetch()` або Web Audio API (через `fetch`) для завантаження локальних `.mp3` або `.json` файлів. Це також викликає помилку CORS.

**Як робити правильно:**
- **Уникати ES6-модулів:** Усі JS-скрипти підключати як звичайні глобальні скрипти (`<script src="...">`). Якщо потрібно передати дані з одного файлу в інший — прив'язувати їх до глобального об'єкта `window` (наприклад, `window.gameData = {...}`).
- **Аудіо:** Для відтворення звуків використовувати стандартний об'єкт `new Audio(src)` або HTML-тег `<audio>`. Вони чудово працюють з локальними файлами без помилок CORS.
- **Дані:** Замість завантаження зовнішніх `.json` через `fetch()`, краще зберігати дані (наприклад, підказки) безпосередньо у вигляді JS-об'єктів у `.js` файлі.

## 2. Обмеження jQuery "Slim"
Для оптимізації застосунок використовує полегшену (slim) версію jQuery (наприклад, `jquery-4.0.0.slim.min.js`).

**Граблі, на які ми наступили:**
- Спроба використати методи анімації (`.animate()`, `.fadeIn()`, `.fadeOut()`, `.slideDown()`) призводила до мовчазних помилок у консолі та зупинки виконання скрипта, оскільки цих методів немає у slim-версії.
- Спроба використати AJAX-методи (`$.ajax`, `$.get`, `$.post`).

**Як робити правильно:**
- **Анімації:** Використовувати звичайні `.show()` та `.hide()` або `.appendTo()` без `fadeIn`.
- **Плавність (CSS):** Якщо потрібна анімація появи, краще додавати/видаляти CSS-класи (`.addClass('show')`), а плавність робити через CSS-властивість `transition`.
- **Скролінг:** Замість `$('html, body').animate({ scrollTop: ... })` використовувати нативний метод браузера `window.scrollTo({ top: ..., behavior: 'smooth' })`.
- **Мережеві запити:** Якщо застосунок потребує запитів (що для офлайн-гри нехарактерно), використовувати нативний `fetch()` (але пам'ятати про обмеження локального запуску, описані вище).

## 3. PWA (Progressive Web App) та робота офлайн
Щоб застосунок можна було встановити на смартфон як окрему програму, потрібні 2 речі: `manifest.json` та Service Worker (`sw.js`).

**Граблі, на які ми наступили:**
- В Android/Chrome іконка застосунку виглядала некоректно або обрізано, оскільки не було вказано властивість `purpose: "maskable"`.

**Як робити правильно:**
- **Маніфест:** Обов'язково вказувати в `manifest.json` іконки з `purpose: "maskable any"` для ідеального відображення на сучасних смартфонах.
- **Кешування:** У `sw.js` потрібно перелічити абсолютно всі файли проєкту (HTML, CSS, JS, усі аудіофайли та зображення), щоб після встановлення гра працювала на 100% без інтернету. При кожному оновленні гри (додаванні файлів) не забувати змінювати версію кешу (наприклад, `CACHE_NAME = 'catch-killer-v0.8.3'`).
- *Примітка:* Service Worker активується тільки при доступі через `https://` або `localhost`, він ігнорується при запуску локального `file:///`.

## 4. QR-сканер
Для сканування карток застосовується бібліотека `html5-qrcode`.

**Граблі, на які ми наступили:**
- QR-коди можуть мати змішаний регістр (наприклад, `http://Crimegames.ru/keymorgan`), а в коді застосунку перевірки були чутливими до регістра, що ламало логіку розпізнавання.

**Як робити правильно:**
- Завжди приводити відсканований URL до нижнього регістра за допомогою `.toLowerCase()` перед порівнянням із внутрішньою базою правильних посилань.
